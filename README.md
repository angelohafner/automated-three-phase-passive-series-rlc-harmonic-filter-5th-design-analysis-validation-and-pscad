# Filtro harmonico passivo no PSCAD 5.1

Exemplo executavel de divisao de correntes harmonicas entre uma carga representada
por fontes de corrente, a rede e um filtro RLC serie em derivacao. A montagem usa
exclusivamente componentes da Master Library e a biblioteca oficial `mhi.pscad`.
Nao ha retificador no circuito.

## Instalacao e execucao

Requisitos: Windows, Python 3.11 ou mais recente, PSCAD 5.1, Master Library,
compilador Fortran reconhecido pelo PSCAD e licenca com automacao habilitada.
As versoes verificadas na maquina estao nos arquivos `diagnostics/environment.json`
e `provenance.json` de cada execucao. O calculo numerico usa NumPy; a analise de
tabelas usa pandas; os graficos usam Matplotlib. SciPy nao e necessario.

No PowerShell, na pasta deste projeto:

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe run_study.py --write-config study_config.json
.\.venv\Scripts\python.exe tools\inspect_installation.py --live
.\.venv\Scripts\python.exe run_study.py --config study_config.json
```

Nao e necessario ativar a venv. Abra o PSCAD uma vez manualmente para confirmar
que a licenca e o compilador funcionam. A opcao `--live` inicia uma instancia
dedicada, inspeciona componentes e a encerra. A consulta de certificados pode
nao estar disponivel em alguns modos de licenciamento; esse fato nao prova que
a simulacao esteja impedida. A compilacao e a execucao sao verificadas separadamente.

Na configuracao, ajuste os caminhos com barras `/`, aceitas pelo Windows e por
`pathlib.Path`, ou use `\\` em strings JSON. Caminho inicial:

```text
C:/Program Files (x86)/PSCAD/5.1.0/bin/win64/pscad.exe
```

O compilador inicial e `GFortran 8.1 (64-bit)`. Escolha o nome exato retornado por
`app.setting_range("fortran_version")` se outro compilador estiver instalado.
O script seleciona o executavel configurado e exige PSCAD 5.1; nao escolhe outra
versao silenciosamente.

Execucoes selecionadas e referencia independente:

```powershell
.\.venv\Scripts\python.exe run_study.py --case without_filter --case tuned_5th
.\.venv\Scripts\python.exe run_study.py --analytical
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Para recalcular a analise de uma execucao ja concluida com seu proprio JSON e
seus CSV, sem executar novamente o PSCAD:

```powershell
.\.venv\Scripts\python.exe run_study.py --analyze-output results\PASTA_DA_EXECUCAO
.\.venv\Scripts\python.exe tools\check_convergence.py results\PASTA_DA_EXECUCAO
```

O segundo comando executa `tuned_5th` com metade do passo de integracao, grava em
cada passo e compara os fasores complexos nos arquivos `convergence.csv` e JSON.
O arquivo `validation_config.json` ativa uma carga linear de 20 kW, uma 3a ordem
de sequencia zero, altera o angulo da 5a e desativa a 11a para uma verificacao
adicional de funcionalidades. Execute-o pelo modo de montagem automatica.

`--analytical` produz dados de uma solucao fasorial linear, identificados como
`ANALYTICAL_REFERENCE`. Esses arquivos nao sao resultados do PSCAD e nao validam
a compilacao, as conexoes ou os transitorios do modelo EMTDC.

Por padrao inicia-se uma instancia dedicada para preservar trabalhos abertos.
Tambem e possivel usar `--port 54321` para conectar uma instancia de automacao ja
iniciada nessa porta. Ela deve conter somente a Master Library, pois o estudo
cria uma nova workspace. Instancias anexadas permanecem abertas ao terminar;
instancias criadas pelo script sao salvas e encerradas.

## Circuito e convencoes

O sistema inicial tem 480 V RMS entre fases e 60 Hz. Tres fontes monofasicas
balanceadas, com neutro aterrado e defasagens 0, -120 e +120 graus, representam
a fonte trifasica. Cada fase possui Rg=0,02 ohm e Lg=0,2 mH em serie.

Diagrama de uma fase, repetido para A, B e C:

```text
  Fonte ideal --- Rg --- Lg --- Isystem <--- PCC <--- Iload --- fonte de corrente
                                             |                         |
                                             |                      neutro
                                             +-- Ifilter --> disjuntor -- R -- L -- C -- neutro
                                             |
                                             +-- Ilinear --> Rlinear -- neutro (opcional)
                                             |
                                           Vpcc (fase-neutro)
```

O sentido de `Iload` e da fonte harmonica para o PCC. `Isystem` sai do PCC em
direcao a rede; `Ifilter` sai do PCC para o filtro. Todos sao medidos por
amperimetros independentes, incluindo a corrente da fonte harmonica. Nao se
substitui corrente medida por comando de controle ou pela diferenca de outras
medicoes.

Na fundamental, `Iload=100 A / 180 deg` representa absorcao de potencia ativa
pela carga, para tensao aproximadamente `277,13 V / 0 deg`. Uma fonte de corrente
com sinal positivo entrando no PCC e angulo zero produziria potencia ativa.
Nas ordens superiores, a corrente representa a emissao harmonica da carga.

O filtro tem tres ramos identicos em estrela aterrada. Esse modelo possui um
retorno ideal de neutro e admite sequencia zero. Nao representa um circuito
trifilar com neutro isolado, nem impedancias de sequencia zero diferentes da rede.
Para esses sistemas, a topologia e o equivalente de sequencias precisam mudar.

A carga linear opcional e resistiva, configurada por `linear_load_kw` (potencia
trifasica na tensao nominal), com Rlinear=VLL^2/Plinear por fase. Quando ativada,
a KCL correta passa a ser:

$$
\underline I_{load,h}=\underline I_{system,h}+\underline I_{filter,h}+\underline I_{linear,h}.
$$

Ela absorve tambem correntes harmonicas se Vpcc estiver distorcida. Nao se pode
omitir esse quarto termo. Com a configuracao inicial, Ilinear=0 e vale exatamente
a relacao de tres correntes solicitada.

## Fontes harmonicas e sequencias

Altere a lista `harmonics` em `study_config.json` ou a tabela de objetos
`Harmonic` em `harmonic_filter/config.py`:

```json
"harmonics": [
  {"order": 1, "rms_a": 100.0, "angle_deg": 180.0, "enabled": true},
  {"order": 5, "rms_a": 20.0, "angle_deg": 0.0, "enabled": true},
  {"order": 7, "rms_a": 14.0, "angle_deg": 20.0, "enabled": true},
  {"order": 11, "rms_a": 9.0, "angle_deg": -10.0, "enabled": true},
  {"order": 13, "rms_a": 7.0, "angle_deg": 30.0, "enabled": true}
]
```

Cada componente aplica:

\[
i_p(t)=\sum_h \sqrt{2}I_h\sin(2\pi h f_1t+\phi_h+h\theta_p),
\quad (\theta_A,\theta_B,\theta_C)=(0,-120,+120)\text{ graus}.
\]

O fator h multiplica a defasagem entre fases, inclusive para sequencia negativa.

| Ordem | Frequencia | Sequencia | B em relacao a A | C em relacao a A |
| ---: | ---: | --- | ---: | ---: |
| 1 | 60 Hz | positiva, 6k+1 | -120 graus | +120 graus |
| 5 | 300 Hz | negativa, 6k-1 | +120 graus | -120 graus |
| 7 | 420 Hz | positiva, 6k+1 | -120 graus | +120 graus |
| 11 | 660 Hz | negativa, 6k-1 | +120 graus | -120 graus |
| 13 | 780 Hz | positiva, 6k+1 | -120 graus | +120 graus |
| 3, 9, 15... | h x 60 Hz | zero | 0 graus | 0 graus |

As sequencias gerais correspondem a h modulo 3 igual a 1, 2 e 0.

A fonte pronta `src_ccin_3` e descrita como fonte trifasica de sequencia positiva;
nao e usada para impor a mesma sequencia a todas as ordens. A implementacao usa
`src_ccin_1`, com controle externo instantaneo `Mag`, uma por fase. Para cada
senoide, o sinal de tempo passa por ganho 2*pi*h*f1, soma da fase inicial, bloco
`trig` em seno/radianos e ganho sqrt(2)*Ih/1000. Somadores combinam as senoidais.
O divisor 1000 converte A para kA, unidade da fonte. A desativacao de uma ordem
zera seu ganho sem alterar as sequencias ou os angulos das outras ordens.

## Dimensionamento RLC

Os valores abaixo sao por fase, para estrela. Qf e a potencia reativa capacitiva
**liquida trifasica** fornecida pelo ramo na fundamental, na tensao nominal.
Ela inclui o efeito do reator e da resistencia. Nao e somente a potencia do capacitor.

$$
Z_f(\omega)=R+j\left(\omega L-\frac{1}{\omega C}\right),\qquad
\omega_t=2\pi f_t,\quad LC=\frac{1}{\omega_t^2},\quad
q=\frac{\omega_tL}{R}=\frac{1}{\omega_tCR}.
$$

Definindo X=1/(omega1*C)-omega1*L>0, o ramo fundamental e R-jX:

$$
S_f=3\frac{V_{ph}^2}{Z_f^*}=\frac{V_{LL}^2}{R+jX},\quad
Q_f=-\Im(S_f)=\frac{V_{LL}^2X}{R^2+X^2}.
$$

Para especificacao por fator de qualidade, tome a=omega_t/omega1-omega1/omega_t
e x_t=omega_t*L. Entao X=a*x_t e R=x_t/q, resultando em:

$$
x_t=\frac{V_{LL}^2a}{Q_f(a^2+q^{-2})},\quad
L=\frac{x_t}{\omega_t},\quad C=\frac{1}{\omega_tx_t},\quad R=\frac{x_t}{q}.
$$

Se `filter_resistance_ohm` for especificada, ela tem precedencia sobre q. Resolve-se:

$$
Q_fX^2-V_{LL}^2X+Q_fR^2=0,\quad
X=\frac{V_{LL}^2+\sqrt{V_{LL}^4-4Q_f^2R^2}}{2Q_f},\quad
L=\frac{X}{\omega_t^2/\omega_1-\omega_1},\quad C=\frac{1}{\omega_t^2L}.
$$

Seleciona-se a raiz de maior reatancia, que tende a VLL^2/Qf quando R tende a zero.
Um discriminante negativo significa especificacao inviavel e interrompe o calculo.

Desprezando R apenas para uma estimativa inicial:

$$
C\simeq\frac{Q_f[1-(f_1/f_t)^2]}{\omega_1V_{LL}^2},\quad
L=\frac{1}{\omega_t^2C},\quad R=\frac{\omega_tL}{q}.
$$

Com 480 V, 30 kvar, 300 Hz e q=50, o dimensionamento completo fornece:

| Grandeza por fase | Valor |
| --- | ---: |
| R | 0,03199944 ohm |
| L | 0,84881163 mH |
| C | 331,57855458 uF |

Na dessintonia mantem-se o capacitor nominal e altera-se L=1/[(2*pi*ft)^2*C].
R e recalculada pelo q do caso, salvo se houver resistencia explicita. Assim a
potencia reativa fundamental pode variar um pouco entre casos; nao se redimensiona
o banco inteiro para esconder o efeito da dessintonia. Os valores efetivos ficam
em `filter_designs.json`. A potencia real depende da tensao real no PCC.

Para uma futura ligacao em triangulo, a tensao em cada ramo e VLL, portanto o
numerador de potencia passa a 3*VLL^2. Nao reutilize estes valores de estrela
diretamente em um triangulo.

## Analise e interpretacao

Duracao: 1 s. Integracao: 10 us. Gravacao: 20 us, ou 50 kHz. A janela principal
contem os ultimos 12 ciclos, [0,8;1,0) s. A janela anterior [0,6;0,8) s permite
verificar estabilidade. O ponto final nao e contado duas vezes.

O ajuste simultaneo por minimos quadrados usa constante, seno e cosseno de cada
ordem de 1 a 25. Para x(t)=a_h*sin(h*omega1*t)+b_h*cos(h*omega1*t):

$$
\underline X_h=(a_h+jb_h)/\sqrt{2},\quad
X_{rms}=\sqrt{\frac{1}{N}\sum_n x_n^2},\quad
THD_{2:25}=100\frac{\sqrt{\sum_{h=2}^{25}|\underline X_h|^2}}{|\underline X_1|}.
$$

O RMS total inclui DC e tudo que houver no sinal amostrado; a THD e limitada a
25 ordens. A DC e exportada separadamente. Angulos de componentes despreziveis e
THD sem fundamental mensuravel sao `NaN`/n.a., e nao zero arbitrario.

A KCL e verificada com residuos de sinal e de fasor:

$$
r(t)=i_{load}-i_{system}-i_{filter}-i_{linear},\quad
\underline r_h=\underline I_{load,h}-\underline I_{system,h}-\underline I_{filter,h}-\underline I_{linear,h}.
$$

O CSV informa parte real, imaginaria, erro absoluto e 100*|r_h|/|Iload,h| quando
a ordem e injetada. Para ordens ausentes, o erro percentual relativo a carga nao
e definido. A verificacao global usa o RMS da carga como base, com piso de 1 A,
e tolerancia inicial de 0,1%, incluindo RMS e pico do residuo temporal.

Cada fasor esperado acima de 10 micro-unidades tambem e comparado com seu proprio
modulo, com tolerancia de 1%. Verificam-se DC inesperada e RMS do residuo que nao
e explicado pela base harmonica, normalizados pelo maior fasor esperado (piso de
1 A ou 1 V). A estabilidade inclui a variacao da DC. As componentes simetricas
positiva, negativa e zero medidas sao exportadas em `sequences.csv` e a sequencia
indesejada deve ficar abaixo de 1% da esperada. As tolerancias sao configuraveis.

Percentuais de modulo solicitados:

$$
A_h=100|I_{filter,h}|/|I_{load,h}|,\quad
S_h=100|I_{system,h}|/|I_{load,h}|.
$$

Em geral A_h+S_h nao e 100%, porque os fasores possuem angulos diferentes.
Para uma decomposicao aditiva use as partes reais das razoes complexas:
100*Re(Ifilter/Iload), 100*Re(Isystem/Iload) e, se necessario, 100*Re(Ilinear/Iload).
Essas projecoes somam aproximadamente 100%, mas podem ser negativas. Nao sao
percentuais de energia dissipada pelo filtro.

A fonte ideal nao contem tensao harmonica para h>1. Sem carga linear, vale:

$$
Z_{g,h}=R_g+jh\omega_1L_g,\quad
\frac{I_{filter,h}}{I_{load,h}}=\frac{Z_{g,h}}{Z_{g,h}+Z_{f,h}},\quad
\frac{I_{system,h}}{I_{load,h}}=\frac{Z_{f,h}}{Z_{g,h}+Z_{f,h}}.
$$

Na fundamental, E1 tambem fornece corrente ao capacitor. A solucao geral usada
na referencia independente inclui esse termo e a carga linear:

$$
Z_{PCC,h}=\left(Z_{g,h}^{-1}+Z_{f,h}^{-1}+Y_{linear}\right)^{-1},\quad
V_{PCC,h}=Z_{PCC,h}\left(I_{load,h}+E_h/Z_{g,h}\right),
$$
$$
I_{system,h}=(V_{PCC,h}-E_h)/Z_{g,h},\quad
I_{filter,h}=V_{PCC,h}/Z_{f,h},\quad I_{linear,h}=Y_{linear}V_{PCC,h}.
$$

Retira-se Zf^-1 no caso sem filtro. A impedancia vista do PCC e calculada com
a fonte de tensao anulada (curto) e as fontes de corrente anuladas (abertas).
Os graficos de impedancia sao calculos em frequencia, nao um frequency scan EMTDC.

Resultados esperados: corrente da carga praticamente identica entre casos;
reducao marcante de 5a ordem na rede; absorcao parcial de 7a, 11a e 13a; melhoria
da tensao no PCC; maior corrente capacitiva fundamental no filtro. Uma rede mais
forte pode conduzir maior parcela da corrente harmonica para o sistema.
O pico de ressonancia paralela abaixo da sintonia aparece na varredura de ZPCC:
aproximadamente 1/[2*pi*sqrt((Lg+Lf)*Cf)] se desprezadas as resistencias.
Outras frequencias podem ser amplificadas. Um filtro de 5a ordem nao garante
reducao em todas as ordens nem atendimento a limites normativos.

Como a carga fundamental inicial esta proxima de fator de potencia unitario,
o filtro capacitivo causa sobrecompensacao. O RMS total da corrente da rede pode
aumentar mesmo com reducao de suas correntes harmonicas. O campo `harmonic_rms`
mostra separadamente o RMS conjunto das ordens 2 a 25. Nos casos de rede forte e
fraca, o parametro da rede tambem mudou: comparar a THD de tensao desses casos
com uma unica referencia sem filtro nao isola o efeito do filtro.

O modelo e linear por construcao, com correntes impostas independentes da tensao.
Nao representa a realimentacao entre distorcao de tensao e emissao de uma carga
nao linear fisica. R, L e C sao ideais; perdas dependentes de frequencia,
saturacao, tolerancias, envelhecimento, protecao e limites termicos/dieletricos
dos equipamentos nao estao representados. O calculo de kvar nao substitui a
verificacao das tensoes dos capacitores e das correntes RMS harmonicas dos ramos.

## Validacao e confiabilidade

1. Execute os testes numericos e a inspecao `--live`.
2. Execute o caso sem filtro; confirme Ifilter desprezivel e Iload aproximadamente
   igual a Isystem em todas as fases e ordens injetadas.
3. Confirme RMS/angulos da carga contra a tabela configurada, inclusive sequencia
   negativa em 5 e 11 e positiva em 1, 7 e 13.
4. Verifique KCL temporal, KCL complexa e comparacao dos fasores com a solucao
   independente, nos CSV `validation.csv` e `harmonics.csv`.
5. Verifique que os fasores das duas janelas em regime permanente concordam
   dentro de 0,5%. Aumente a duracao se houver transitorios residuais.
6. Repita com 5 us de integracao e 10 us de gravacao. Compare os fasores, o RMS
   e a THD. Diferencas que diminuem com o passo sao de discretizacao; erros que
   permanecem grandes sugerem polaridade, unidade, topologia ou controle incorretos.
7. Para dessintonia e q elevado, observe ZPCC e aumente a janela se o amortecimento
   for lento. Nao apenas remova a verificacao de estabilidade.

O script verifica existencia de componentes, nomes de parametros, portas ativas,
compatibilidade eletrica/sinal e dimensoes. Usa coordenadas reais de `ports()` e
rotacao pela API. As conexoes e os componentes ficam documentados em JSON.
Mensagens de compilacao sao salvas; saida ausente, incompleta, nao finita, canais
duplicados e tempos inconsistentes causam erro. As colunas OUT sao mapeadas pelo
indice PGB e pelo nome em INF, nao pela ordem presumida de insercao.

`status.json` distingue execucao terminada de validacao aprovada. Codigo de saida
0 significa estudo terminado com verificacoes aprovadas; 2 significa dados
processados mas validacao reprovada. Excecoes produzem `failure.txt`. Nao se converte
automaticamente uma falha do PSCAD em resultado analitico.

## Inspecao pela API

Veja tambem `tools/inspect_installation.py`. Exemplos para uma instancia conectada:

```python
from pathlib import Path
import mhi.pscad
import xml.etree.ElementTree as ET

app = mhi.pscad.connect(port=54321)
print(app.version)
print(app.projects())
library = app.project("master")
print(library.definitions())
definition = library.definition("src_ccin_1")
print(ET.tostring(definition.xml, encoding="unicode"))
project = app.project("tuned_5th")
canvas = project.canvas("Main")
component = project.find("master:src_ccin_1", "HarmonicSource_A")
print(component.parameters())
print(component.iid, component.defn_name, component.location, component.orient)
print(component.ports())
print(component.port("Mag"))
print(project.parameters())
print(project.parameter_range("PlotType"))
print(app.setting_range("fortran_version"))
print([(item.iid, item.defn_name) for item in canvas.find_all()])
for item in canvas.find_all():
    if callable(getattr(item, "vertices", None)):
        print(item.iid, item.defn_name, item.vertices())
```

`properties()` nao existe no `UserCmp` inspecionado; as propriedades reais sao
acessadas pelos atributos acima. `get_port_location()` e uma API antiga; utiliza-se
`ports()`/`port()`. As escolhas podem aparecer como strings normalizadas
(`YES`, `SIN`, `OUT`) mesmo quando o XML usa indices numericos. O codigo confirma
os parametros pela API antes de atribuir e conserva o XML real para consulta.
O catalogo offline conserva portas e condicoes do XML; somente `ports()` informa
quais estao efetivamente ativas em uma instancia configurada. `vertices()` mostra
o percurso real dos fios e barramentos retornados pelo canvas.
